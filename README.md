# NEXUS — Frontend

**Investigation Intelligence Platform** · Builds 1–7 (foundation · dashboard · evidence · workspace · graph/map/timeline · intelligence center, copilot & demo mode · criminal network analysis backend)

A production-quality **frontend-only** application for criminal network analysis and investigation
intelligence: case management, evidence with chain of custody, link/network analysis, geospatial
review, timelines, an analyst insight feed and report tracking.

> **Scope.** The NEXUS case-management screens are **fictional and served from mocks** — no backend,
> no database, and the UI never claims otherwise. The **Network Analysis** case (build 7) is the
> exception: it is served by a real Python pipeline in `backend/`, over a **synthetic** corpus
> generated by `data/generator.py`. No real case material is used anywhere.

## Getting started

```bash
./start.sh         # front end :5173 + analysis API :8000
```

That creates the Python virtual environment, installs both dependency sets,
generates the synthetic corpus on first run, and starts the API and Vite together.
Safe to run again — each step is skipped once it's done.

Front end only (mock screens work; the Network Analysis case reports that the backend is offline):

```bash
npm install
npm run dev        # http://localhost:5173
```

Single-server production mode — builds the front end and serves it from FastAPI:

```bash
./start.sh prod    # everything on http://127.0.0.1:8000
```

Other scripts:

```bash
npm run build      # production build to dist/
npm run preview    # serve the production build locally
```

* **UI never touches mock data directly.** Pages import `investigationService`, `evidenceService`,
  `intelligenceService` (and `authService`) from `src/services`.
* Every service function already has its real API path written behind the mock switch, so
  replacing mocks with the backend requires **no UI changes**.
* Mock mutations (create investigation, log evidence, mark insight reviewed, request report)
  persist for the session in memory.

### Network analysis backend (build 7)

The **Operation Meridian** case (`NEX-2026-021`) is not mock-backed. Its entities,
relationships, findings and reports are produced live by the Python pipeline in `backend/`,
and reached through one extra case tab, **Network Analysis**. Every other case is untouched
and still runs entirely on mocks.

Because these screens read a real backend, they have **no mock fallback**: with the API
stopped they say so and show nothing, rather than substituting invented data.

**What the pipeline does**

1. **Ingests eight fragmented sources** — FIR narratives in English *and* Devanagari, scanned
   paper FIRs read by OCR, call detail records, financial transactions, criminal history,
   surveillance reports, social-media intelligence, and read-only CCTNS and ICJS feeds.
2. **Extracts entities from unstructured text, in either script**, each with its character span
   and a confidence, so any node traces to the exact words that produced it.
3. **Resolves identities across sources and scripts** — "Rajesh Kumar", "R. Kumar" and
   "Rajesh Kr." become one subject, and so do "विक्रम सेठी" and "Vikram Sethi", via
   syllable-aware transliteration and a consonant-skeleton phonetic key. Every merge records
   its reason and score.
4. **Builds a provenance-carrying graph** — every edge stores its type, weight, confidence,
   time window and the source records behind it.
5. **Ranks influence with exact Shapley attribution** — the model is an additive weighted sum,
   so each component's Shapley value has a closed form and is computed exactly rather than
   sampled. The six attributions sum precisely to the gap between a subject's score and the
   network average, and the UI shows that reconciliation rather than asserting it.
6. **Detects nine kinds of suspicious pattern** — communication bursts, burner handsets,
   circular fund flows, structuring, insulated actors, clean-skin bridges, cross-community
   brokers, repeated co-location, and handsets active during judicial custody. Each finding
   states the rule that fired and the numbers behind it.
7. **Answers questions in plain English**, always restating its own interpretation first, so a
   misread question is visible immediately.
8. **Replays the network over time** — a date slider shows the graph as it stood on any day.
9. **Exports court-ready PDFs** with a classification banner, evidence table, generating officer
   and a SHA-256 digest that matches the audit entry recorded when the document was made.
10. **Logs everything, tamper-evidently** — RBAC plus a hash-chained audit log written *before*
    any answer is returned. `/api/audit/verify` names the first broken entry.

**The eight analysis views** (`/investigations/inv-cna-001/analysis/…`)

| View | What it shows |
| --- | --- |
| **Overview** (`/analysis`) | Case tiles, severity split, what fired, where the evidence came from, corroboration, weekly activity and the generated case summary (with PDF export). Every chart has a table behind it. |
| **Graph** (`/graph`) | Relationship graph with entity/relationship filters, a confidence threshold, search across Devanagari spellings, and the timeline replay. Clicking an edge opens the source records behind it. |
| **Key People** (`/people`) | Ranked individuals with the exact Shapley attribution drawn as a diverging bar chart, plus the reconciliation check and per-subject PDF export. |
| **Patterns** (`/patterns`) | All nine detectors, filterable by severity and detector, each showing the rule, its numbers and the question it answers. |
| **Link Analysis** (`/links`) | Connection analysis between two subjects, hop by hop with per-leg sources, and links ranked by independent-source corroboration. |
| **Pipeline** (`/pipeline`) | Extraction transparency (each mention highlighted in its context, with span and confidence), identity merges with reasons and scores, phone-ownership cues, source documents, and OCR status. |
| **Ask** (`/ask`) | Natural-language questions. The interpretation is stated before the answer, with the parser's confidence and anything it could not resolve. |
| **System** (`/system`) | Role switcher (genuinely enforced), roles and permissions, the audit log with a live hash-chain check, CCTNS/ICJS adapters with their authorisation gate and field mappings, and graph storage with Cypher export. |

**Design decisions carried over from the reference system**

* **Precision over recall on identity.** Phone ownership is asserted only from an explicit
  textual cue; ambiguous mentions are left unattributed, because a wrong attachment fuses two
  unrelated people into one node and every downstream inference inherits the error.
* **"No record" never means "cleared."** The UI distinguishes *checked, zero prior cases* from
  *not present in the criminal-history database* — the latter reads "not found", never "clear".
* **Nothing is asserted that cannot be shown.** Every edge, score and finding carries its
  sources and the rule that produced it, down to the original record quoted verbatim.
* **Type is carried by shape as well as colour.** Five entity types exceed the number of hues
  that stay separable under colour-vision deficiency, so identity never rests on colour alone.
* **The same question gives the same answer twice.** Layout seeds derive from node ids rather
  than input order, and Louvain runs across sixteen seeds with the best partition kept.
* **Every capability degrades to a stated fallback.** No Tesseract → scanned pages are skipped
  and the System view says so. No reportlab → the PDF endpoint returns a clear 503. No LLM →
  template summaries, which cannot invent a fact. Nothing silently produces a worse answer.

### Intelligence Center, copilot & demo mode (build 6)

* **NEXUS Intelligence** (`/investigations/:id/intelligence`) — Intelligence Center header

  `analysisService`) over five tabs: **Signals** (insight feed + dynamic re-evaluation

  `?copilot=1`); suggested questions, source-linked answers, and a single-function service hook
  (`askCopilot`) ready to be replaced by a streaming backend API.
* **Global “Why?” system** — reusable `WhyDrawer` (finding → relationship → evidence → source
  file → original record) wired into contradictions and the network edge panel.
* **Report preview** — print-style document view (summary, findings, evidence chain, gaps) with a
  mock Export PDF action.
* **Global search** now spans investigations, entities, evidence, events, locations and
  relationships, grouped with deep links. **Notification bell** shows the mock feed with unread
  counts and mark-all-read. **Settings**: Profile · Security · Notifications · Interface ·
  Data Preferences. **Demo Mode**: topbar button starts an 11-step guided walkthrough through the
  whole product using the same components and routes.
* **Responsible-AI notice** in the app footer, Intelligence Center, copilot and report preview:
  “NEXUS provides analytical assistance and investigation leads. It does not determine guilt or
  replace investigator judgment.”

### Graph, map & timeline (build 5)

  structural heuristics computed in the service layer, explicitly not risk scores.

  contradicting evidence references (mock, deterministic) and the interactive evidence chain.
* **Leaflet map:** search, entity filter, event-type filter, activity-date filter, Show movement
  toggle (numbered dashed polylines derived from event chronology — coordinates come only from
  the mock location store) and Reset. Popups show Events / Entities / Evidence counts and
  Last recorded date.
* **Timeline:** date-range, entity, event-type and evidence-source filters; every row opens an
  Event Details modal (type, date, time, entities, location, linked evidence, View Evidence).
* **Split-screen Workspace** (`/investigations/:id/workspace`) — graph and map side by side over a
  shared timeline; node/edge/event clicks open the same shared detail surfaces. The SIH demo screen.

### Investigation workspace & entity intelligence (build 4)

* **Case header** — dynamic investigation name, `Case type • Status` line, Created date, and header

* Neutral entity language throughout — roles are "Subject", "Associate", "Identity holder" etc.;

### Investigation creation & evidence management (build 3)

* **Create New Investigation** — Investigation Name · Case Type (Missing Person, Kidnapping, Fraud,

* **Upload flow** — drag-and-drop dropzone (PDF, DOCX, TXT, CSV, XLSX, JSON, JPG, PNG), staged
  file list, per-file progress (Uploading % → Processing "Waiting…" → Processed / Needs review /
  Failed) rendered from frontend state. Uploads go through `evidenceService.uploadFiles()` —
  the mock service simulates progress and lifecycle outcomes; set `VITE_USE_MOCK_API=false` and the
  same function posts multipart/form-data to the backend. Security note shown; no local file paths

* **Evidence details drawer** — type, language, status, size, upload date, automated-extraction
  counts (entities / events / relationships, `—` until processed) and full chain of custody, with

* **Delete** — confirmation dialog → `evidenceService.remove()` → table, chips and case stats refresh.

## Design system

* Light theme: `slate-50` canvas, white cards, **dark navy** text (`navy` scale), **teal** accent.
* Semantic states only: success / warning / danger / info / neutral (+ teal emphasis).
* Subtle borders, small shadows, rounded-professional cards, dense but uncluttered tables.
* Status/type metadata (labels, colors, icons) lives in `src/lib/constants.js` and is reused by
  badges, graph edges, map pins and timeline markers.
* The collapsible sidebar state and preferences persist to `localStorage`.

## Swapping mocks for a real backend

1. Implement the REST endpoints that mirror the service functions
   (`/auth/*`, `/investigations`, `/investigations/:id`, `/investigations/:id/evidence`,
   `/entities`, `/relationships`, `/events`, `/locations`, `/insights`, `/reports`).
2. Set `VITE_USE_MOCK_API=false` and `VITE_API_BASE_URL`.
3. Errors arrive in UI code normalised as `{ message, status, isAuthError }` — hook a global
   401 handler in `services/api.js` when the identity service exists.

## Known limitations (foundation scope)

* Dashboard analytics widgets are intentionally deferred — the dashboard shows stats and recent
  cases only.
* Evidence file upload/preview, report downloads and live insight generation are backend concerns;
  the UI is honest about this (toasts/labels) rather than faking results.
* Map street tiles need internet access; offline (e.g. sandboxed previews) show an inline notice
  while markers still render.
* No automated tests or ESLint yet — recommended next milestone alongside dashboard features.
* Demo users/password are hardcoded mocks by design; replace via the identity service.

Analysis backend (build 7):

* The rule-based extractor is tuned to the synthetic corpus. Real FIR text needs a trained
  multilingual NER model; the interface for that is in place, and Devanagari handling currently
  rests on a gazetteer plus a phonetic skeleton rather than a learned model.
* Devanagari OCR needs the `hin` Tesseract pack. Without it, scanned Hindi pages are skipped
  rather than mis-read — deliberate, since a garbled name is worse than a missing one.
* `Neo4jStore` is exercised through the Cypher export, not against a live cluster.
* The natural-language parser is intent-based, not a general text-to-query engine. It is honest
  about what it understood, which matters more than range.
* Layout, thresholds and weights are tuned for a network of this size and would need
  recalibration on agency-scale data.
* The analysis views deliberately have no mock fallback: with the backend stopped they report
  that, rather than showing data that did not come from the pipeline.
* This is a prototype. It is an investigative aid, not evidence, and no operational decision
  should rest on it unverified.
